## 1. 引言

### 1.1 目的

本文档定义个人导航网站的全部功能与非功能需求，作为实施的唯一依据（spec 先行，防止过度工程）。

### 1.2 范围

开发一个纯前端个人导航站，桌面端由四页组成（第 1 页导航、第 2 页大盘云图、第 3 页天气预报、第 4 页台风路径与警报），页间用滚轮/键盘/圆点整页翻动；移动端退化为单列长页。第 1 页包含：大图标首页、分类标签页、自定义背景（毛玻璃质感）、搜索框、响应式布局与暗色模式。数据以 YAML 文件维护，通过 `git push` 更新；第 2~4 页为外部公开数据源的只读消费，不参与 YAML 维护。

### 1.3 定义与缩写

| 术语 | 含义 |
|------|------|
| pinned 网站 | YAML 中标记 `pinned: true` 的网站，显示于首页大图标区 |
| 降级链 | favicon 获取失败时按优先级回退的加载策略 |
| 字母坞 | 图标加载全部失败时的兜底：网站名首字母彩色方块 |
| deck / 页 | 四块 100vh 的 `.page` 纵向排成一条 deck，靠 `transform` 位移整页切换 |
| 桌面端 | 满足 `(min-width: 861px) and (hover: hover) and (pointer: fine)` 的环境；仅此环境启用翻页 |
| 云图 / treemap | 第 2 页的市值面积 + 涨跌配色方块图，自绘 squarified 布局，非 iframe |
| 标签区 | 第 1 页的分类标签栏 `#tabs` 本身（不含其下方内容区），滚轮在此翻标签 |
| WMO 代码 | 第 3 页天气现象编码（接口字段 `weather_code`），本项目自映射为中文标签与配色分组 |
| 美标 AQI | 第 3 页空气质量口径（接口字段 `us_aqi`），与国内 AQI 数值不同，界面标签须写明"美标" |

### 1.4 读者与维护

个人项目，作者即唯一用户与维护者。需求变更直接修改本文档并注明版本。

## 2. 总体描述

### 2.1 产品定位

单用户、单设备为主的个人浏览器起始页/导航页。更新频率低，观感优先，维护摩擦可接受（改 YAML + push）。

### 2.2 技术约束（硬性）

- **纯静态前端**：HTML + CSS + 原生 JavaScript，无框架、无构建步骤。
- **零 CDN 依赖**：js-yaml 以 `js-yaml.min.js` 文件形式下载到仓库本地引用。自有 JS/CSS 之外不引入任何第三方脚本（云图为自绘，见 FR-12）。
- **无后端、无数据库、无 API key**：不使用任何需要密钥的外部服务；允许消费**匿名、只读、CORS 开放**的第三方公开接口（金融界行情网关见 FR-12，Open-Meteo 见 FR-13）与第三方页面的 iframe 嵌入（见 FR-14）。
- **部署**：GitHub Pages 直接发布仓库根目录（或 `/docs`），push 即生效。

### 2.3 运行环境

- 现代桌面浏览器（Chrome/Edge/Firefox 近两个大版本）为主，移动端浏览器可用。
- 桌面端为四页翻页形态；移动端（触屏 / 窄屏）退化为单列长页，滚动行为与 v1.3 一致（FR-11.6）。
- 访问者网络环境为中国大陆（影响 favicon 源选型，见 FR-4；也决定第三方接口必须境内可达）。

### 2.4 假设与依赖

- js-yaml v4.x 本地文件可用且兼容目标浏览器。
- 任何第三方 favicon 服务（含国内聚合源）在中国大陆网络下均可能不可达，故字母坞兜底必须"可控且必好看"——它是唯一由本项目完全掌控的视觉元素；外部源只是提高真实图标命中率的"尽力而为"层级。
- `backdrop-filter` 在目标浏览器可用；不支持时降级为半透明纯色卡片（优雅降级，不算缺陷）。
- **外部数据源属"尽力而为"依赖**：`gateway.jrj.com` 的 `quot-dpyt` 接口须保持 `Access-Control-Allow-Origin: *` 且不改路径/字段；`api.open-meteo.com` 与 `air-quality-api.open-meteo.com` 须保持匿名可用 + CORS 开放、支持多地点且不改字段；`typhoon.slt.zj.gov.cn` 须不设 `X-Frame-Options`/`frame-ancestors`。任一失效时，对应页显示可读错误提示或空壳，**不得**影响第 1 页与整体渲染（同 FR-1.3 的处置原则）。实测基线：2026-10-06 三类源均可用（含 `OPTIONS` 预检放行、多地点回数组、`us_aqi` 有值）。

## 3. 功能需求

### FR-1 数据层：YAML 单一数据源

- FR-1.1 全部导航数据与站点配置存于 `data/sites.yml`（`settings` / `searchEngines` / `backgrounds` / `categories` / `weather`），前端通过 `fetch` + js-yaml 在运行时解析。
- FR-1.2 首页大图标区与分类标签页**共享同一份数据**：首页 = 各分类中 `pinned: true` 网站的合集，不单独维护列表。
- FR-1.3 YAML 加载或解析失败时，页面显示可读的错误提示（含错误行信息），不白屏。
- FR-1.4 数据更新方式仅为：编辑 YAML → commit → push。不提供页面内编辑。

**YAML Schema（规范，实现必须兼容）：**

```yaml
settings:
  title: 我的导航                    # 页面标题
  background: assets/bg/dusk.svg    # 默认背景图（仓库相对路径）
  bgBlur: true                      # 背景图模糊开关

searchEngines:                      # 搜索框引擎列表，首个为默认
  - { name: Google, url: "https://www.google.com/search?q=%s" }
  - { name: 百度,   url: "https://www.baidu.com/s?wd=%s" }
  - { name: Bing,   url: "https://www.bing.com/search?q=%s" }

backgrounds:                        # 页面切换器列出的候选背景
  - assets/bg/dusk.svg

categories:
  - name: 常用工具                  # 分类名，即标签页名
    sites:
      - name: GitHub                # 网站名（用于字母坞与 alt）
        url: https://github.com
        pinned: true                # 可选，true 则出现在首页大图标区
        desc: 可选的文字解释，悬停卡片以 tooltip 展示
```

- `pinned` 缺省视为 `false`。
- `%s` 为搜索词占位符。

### FR-2 首页大图标区

- FR-2.1 首页默认视图：搜索框（FR-6）+ pinned 网站大图标网格。
- FR-2.2 大图标尺寸 ≥ 64px，卡片带悬停反馈，点击新标签页打开。
- FR-2.3 pinned 网站按 YAML 中分类顺序、分类内顺序排列。

### FR-3 分类标签页

- FR-3.1 顶部标签栏列出 YAML 中全部分类 + "首页"。
- FR-3.2 切换标签页无刷新切换内容区；当前标签高亮。
- FR-3.3 分类内网站以较小卡片网格展示（图标 + 名称）。
- FR-3.4 标签栏随模型构建一次后复用：切换标签**只更新当前项状态**（`aria-current`），不得每次切换清空并重建整条标签栏（会连带重建全部监听器）。重复点击当前标签不得触发内容区整体重建。当前项状态用 `aria-current` 表达而非 `aria-selected`（按钮未声明 `role="tab"`，后者属无效 ARIA）。

### FR-4 图标降级链

按以下优先级加载，任一失败自动进入下一级，全程不阻塞渲染：

1. **国内可达的 favicon 聚合源（可配置，默认 `https://api.iowen.cn/favicon/{domain}.ico`）**：规避 Google `s2/favicons` 在中国大陆经常不可达的问题，返回较清晰的图标。源地址为单一常量（`js/icons.js` 的 `FAVICON_PRIMARY`），换源只改一处；备选含 `ico.fun`、`favicon.im`（SVG 矢量）、`icon.horse` 等，均无 API key。
2. `<origin>/favicon.ico`：站点自有图标，作为第二外部尝试。
3. 字母坞：网站名首字符 + 由域名哈希决定的稳定渐变底色方块，并在 64px 大图标（pinned）上附加域名小字，保证兜底视觉精致。

- FR-4.1 加载走浏览器 HTTP 缓存（`<img>` 标签），同设备不重复请求。
- FR-4.2 每级监听 `onerror` 触发回退；三级全失败时保证字母坞必然渲染。
- FR-4.3 指向第三方聚合源的图标请求必须设 `referrerpolicy="no-referrer"`（不向外部泄露本站地址，见 NFR-4），并设 `decoding="async"` 使解码不阻塞主线程。首屏（pinned）图标用 `loading="eager"`，分类内小图标用 `loading="lazy"`。

### FR-5 背景与毛玻璃

- FR-5.1 背景图资源存于仓库 `assets/bg/` 目录，候选清单来自 `backgrounds`。
- FR-5.2 生效背景 = localStorage 中用户选择 → 缺省回落到 `settings.background`。
- FR-5.3 背景选择在设置页完成（见 FR-10）。
- FR-5.4 背景模糊开关（`bgBlur`）：默认取 `settings.bgBlur`，用户可在设置页覆盖并持久化。
- FR-5.5 导航卡片统一 `backdrop-filter` 半透明毛玻璃质感；不支持时降级半透明纯色。
- FR-5.6 背景路径来自 YAML，写入 CSS `url()` 前必须转义 `"` 与 `\`：既防止路径内容突破 `url()` 注入样式，也保证含空格的路径仍能正常渲染，不得直接字符串拼接。
- FR-5.7 `backdrop-filter` 只允许存在于卡片、标签、搜索框、遮罩这几层视觉主体上；**不得**在浮窗面板与站点 tooltip 这类已处于模糊祖先内部、且自身底色接近不透明（约 ≥90% alpha）的元素上再叠一层——嵌套模糊根会重复采样并额外占用 GPU 纹理，视觉收益接近零。v1.2 追加：整体背景模糊开启（`body.bg-blur`）时，上述各层的背景**已经是模糊图**，必须跳过元素级 `backdrop-filter`——对模糊结果再采样纯耗 GPU 而视觉无收益。

### FR-6 搜索框

- FR-6.1 首页顶部居中搜索框，引擎可从 `searchEngines` 列表切换，记住上次选择（localStorage）。
- FR-6.2 输入后 Enter 跳转 `url` 中**所有** `%s` 替换为 `encodeURIComponent(关键词)` 后的地址，新标签页打开。注意 `String.prototype.replace` 只替换首个匹配，多占位符 URL 会残留字面量 `%s`，故实现须按全部占位符替换（如 `split('%s').join(...)`）。

### FR-7 响应式

- FR-7.1 CSS Grid 自适应列数：桌面 6–8 列，平板 4 列，手机 2–3 列。
- FR-7.2 分类标签在宽度压缩时自动换行显示，不使用水平滚动条。
- FR-7.3 鼠标悬停在**分类标签栏 `#tabs` 本身**内时，滚轮切换分类标签页，纵向环形（末项向下回首页、首项向上回末项）。约束：
  - 判定范围只到标签栏，**不含其下方的内容区**：内容区滚轮用于 FR-11 的整页翻页。二者若都吃内容区，用户永远滚不出第 1 页。
  - 仅接管纵向滚动（`|deltaY| > |deltaX|`），触控板横向手势放行。
  - 累积位移达阈值（40px）才算一次切换，且切换后锁定至滚动停歇（220ms），防止一次惯性滑动连跳多个分类。
  - 设置浮窗打开时（`draft` 非空）不接管，让浮窗自身滚动。
  - 该行为以 `passive:false` 拦截默认滚动，故悬停标签栏时页内不滚动——这是 FR-7.3 的既定代价，v1.2 曾以"阻塞滚动、触控板难触发"为由移除，v1.3 应用户要求恢复，v1.4 把判定范围从 `#stage` 收窄到 `#tabs`。
  - 滚轮监听点全站唯一，位于 `js/deck.js`（见 FR-11.3）；`ui.js` 只回答"指针是否在标签栏内"与"翻一格标签"。

### FR-11 整页翻页（仅桌面端）

- FR-11.1 站点由四块 100vh 的 `.page` 纵向组成一条 deck：第 1 页导航、第 2 页大盘云图、第 3 页天气预报、第 4 页台风路径与警报。桌面端一次只显示一页，切换靠 `transform: translateY(-N×100vh)` 位移，带 .52s 过渡。
- FR-11.2 三种翻页入口：滚轮（指针不在标签栏、且页内滚动区已到边界时）、键盘（`↑`/`↓`/`PageUp`/`PageDown`/`Home`/`End`）、右侧圆点（点击直达，`aria-current` 标当前页）。
- FR-11.3 滚轮路由优先级：① 非桌面端 → 完全放行，交浏览器原生滚动；② 设置浮窗打开 → 放行；③ 横向手势为主 → 放行；④ 指针在 `#tabs` 内 → 翻标签（FR-7.3）；⑤ 指针所在页的 `[data-scroll]` 区还能朝该方向滚 → 放行，先滚内容；⑥ 其余 → 翻整页。翻页动作的锁定时长须覆盖整段过渡（560ms > .52s），否则过渡中排队的手势会连翻两页。
- FR-11.4 页间**不环形**：首页向上、末页向下越界即停。与标签的环形语义不同源——标签是同类项轮转，页是三个不同去处，越界回绕会让人找不到自己在哪。
- FR-11.5 每页内容超高时由页内 `[data-scroll]` 容器自滚（第 1 页 pinned 多、窗口矮是常态），滚到边界才翻页（FR-11.3 ⑤）。
- FR-11.6 **分页只适用于电脑，手机不适用**：桌面判定 = `(min-width: 861px) and (hover: hover) and (pointer: fine)`。触屏/窄屏下 deck 回到普通文档流，四页纵向堆叠、原生滚动、圆点隐藏、`transform` 清空。该条件串在 `js/deck.js` 与 `css/style.css` 各写一次，是同一份契约，改一处必须改两处（同 FR-8.4 的内联脚本契约）。
- FR-11.7 重型内容按需加载：云图数据只在首次进入第 2 页时开始请求，天气数据只在首次进入第 3 页时开始请求，台风 iframe 的 `src` 只在首次进入第 4 页时写入；离开某页与切到后台标签页（`visibilitychange`）时停掉该页的轮询。移动端无翻页事件，故启动即就绪（否则后三页永远空白）。
- FR-11.8 左上角齿轮在桌面端为跨页固定元素，其容器 `pointer-events: none`、仅按钮本身 `auto`——否则顶栏那条横带会吃掉一整条滚轮热区。第 2、3 页页头左侧留 62px 让开齿轮。

### FR-12 第 2 页 · 大盘云图

- FR-12.1 数据源为金融界公开行情网关（`POST https://gateway.jrj.com/quot-dpyt/v1/market` 取市值树，`POST /quot-dpyt/v1/hq` 按维度取行情），响应带 `Access-Control-Allow-Origin: *`，浏览器直连、无需 key 与代理。**不采用 iframe 嵌源站**：源站整页带约 360px 的站头与热榜，CSS 负偏移裁切依赖对方布局、改版即错位，且跨域 iframe 内的滚轮父页拿不到。
- FR-12.2 渲染为**自绘 squarified treemap**（`js/treemap.js`，纯几何、无 DOM）：面积 = 市值占比，三级嵌套（行业 → 二级 → 个股），每级顶部留一条标签带，格子小于 `minW×minH` 时不预留标签带。为此起见不引入 ECharts（约 1MB，会把 NFR-5 的体积预算整个击穿）。
- FR-12.3 六个维度可切换，取值语义与色阶阈值**原样对齐源站**：`chg`/`chgw`/`chgm`/`chgy` 接口回小数（×100 后进色阶），`netin` 回元（÷1e4 得万），`pefwd` 回原值且色带反转（低 PE 红、高 PE 绿）。缺数据（停牌）回落 `rgb(79,69,84)`。
- FR-12.4 亚像素叶子（宽 < 7px 或高 < 7px）不进 DOM；文字按格子尺寸分两级显隐（先名称、够大再加数值）。整棵树 5000+ 只股票，实际落屏节点约 200–2000 个。
- FR-12.5 节点元素按 sid / 路径为键跨帧复用，每轮只改样式与文本，不整块重建。**几何按「树引用 + 容器尺寸」缓存**：`packTree` 的结果只在容器尺寸变化（`ResizeObserver` 触发）或树本身更换时才重算；12s 轮询与切维度都不改几何（市值树权重恒定、尺寸未变），故走**纯重绘**——只改格子的颜色/文字/`info`，跳过 `packTree` 与 `place` 的坐标写入。否则每轮都要对全树 5000+ 节点重排，与本条「每轮只改样式与文本」相悖。（不支持 `ResizeObserver` 的浏览器退化为"进入本页时排一次"，不算缺陷。）
- FR-12.6 悬停叶子显示浮动信息（名称/代码、现价、当前维度值、全市场占比）。占比须由三级 `scale` 逐级相乘得到——接口给的 `scale` 是**占父级**比重，直接显示会把"占板块 35%"念成"占大盘 35%"。悬停绘制**每帧合帧一次**（`mousemove` 只登记待绘状态、`requestAnimationFrame` 里统一画），且 `#market` 与 tooltip 的矩形缓存复用（前者随重排作废、后者随内容重建作废）：稳定悬停期间只写 `transform`、不读布局，避免在上千格子的子树上逐事件强制回流。
- FR-12.7 每 12s 轮询一次（对齐源站 `dpytData` 周期），页头显示接口回报的交易日与时间；请求失败保留上一帧画面并显示错误行，不白屏、不清空。
- FR-12.8 图例（9 档色阶 + 刻度）随维度切换重绘，色块不许被 flex 压缩——压扁后刻度文字会与右侧时间戳叠成一团。

### FR-13 第 3 页 · 天气预报

- FR-13.1 数据源为 Open-Meteo 两个匿名接口：`api.open-meteo.com/v1/forecast`（当前 + 7 天逐日）与 `air-quality-api.open-meteo.com`（美标 AQI + PM2.5/PM10），均实测回 `Access-Control-Allow-Origin: *`，无需 key、无代理。**不采用中国天气网**：其城市页虽可 iframe（无 `X-Frame-Options`），但带站头/导航/广告；其 JSON 接口 `d1.weather.com.cn` 实测**无 Referer 直接 403、带 Referer 才 200**，浏览器无法伪造该头，故数据路线不通。
- FR-13.2 城市来自 `data/sites.yml` 的 `weather.cities`（`name` + `lat` + `lon` 十进制度），**页内不做城市搜索**。`data.js` 归一化时按单条原则校验：`name` 为空、坐标不可数值化或超出 ±90/±180 的条目直接丢弃，不影响其余数据。加/删/排序城市只改 YAML + push（NFR-3）。
- FR-13.3 多城合并请求：两个接口都支持多地点（`latitude=a,b,c&longitude=…`，按请求顺序回一个数组），故 **N 座城市固定 2 个请求**，不是 2N。**单地点时接口回对象而非数组**，读取侧必须归一为数组再对齐。坐标在拼 URL 前一律 `Number()` 校验（YAML 值按外部输入对待）。
- FR-13.4 城市切换是**纯视图状态**：页头标签栏（名称 + 当前温度角标，数据已在本地，切换零请求）选城，选中项用 `aria-current` 表达；不落 localStorage、不重新取数——与云图维度标签同级，属"这一页看什么"而非站点设置（FR-10.2）。
- FR-13.5 要素：当前（温度 / 体感 / 湿度 / 风速 / 降水 / 天气现象）+ 未来 7 天逐日（今天·明天·星期、现象、降水概率、高低温）+ 空气质量块。WMO `weather_code` 自映射为中文标签并归入 7 个配色分组（晴 / 云 / 雾 / 毛毛雨 / 雨 / 雪 / 雷暴，阵雨并入雨色系），分组只驱动一条侧栏强调色，卡片本体保持统一玻璃底，不额外引入 `backdrop-filter` 层（FR-5.7）。
- FR-13.6 空气质量是**附加信息**：该请求单独 `.catch`，失败降级为全城无 AQI 块，不得拖累主数据。口径为美标 `us_aqi`，界面标签须写明"美标"——与国内 AQI 数值不同，混用会误导。
- FR-13.7 日期标签以接口回报的 `daily[0]` 为"当地今天"顺推（今天 / 明天 / 星期 X）。不得用 `new Date('YYYY-MM-DD')` 的 UTC 解析去推星期，那会在东八区整体偏一天。
- FR-13.8 每 10 分钟刷新一次（上游逐小时更新，更快无意义）；失败保留上一帧画面并显示错误行；页头"刷新"按钮立即补一次并重置计时，避免与到点轮询撞成两个请求。`weather.cities` 为空时不发起请求，直接报"cities 为空"。
- FR-13.9 每次渲染只重建 `#weather-grid`。状态行与错误行必须留在该网格之外：它们与卡片同级，若图省事整体清空容器（`textContent = ''`），状态节点会被一起删掉，此后所有提示都写进游离节点——页面从此不再报告加载与失败。
- FR-13.10 **数据编辑器必须认识 `weather` 段**：`tools/yaml-editor.html` 的导出是白名单式重建（`clean()` 只吐已知键），任何未纳入的顶层键都会在保存时被静默抹掉。故新增顶层数据段时，编辑器的 `blankModel` / `loadText` / `clean` / 表单四处须同步跟进，且表单里坐标按字符串编辑、导出时数值化，非法值标红并在检查区列明。

### FR-14 第 4 页 · 台风路径与警报

- FR-14.1 以 iframe 嵌入浙江省水利厅台风路径实时发布系统（`https://typhoon.slt.zj.gov.cn/`）。源站无 `X-Frame-Options`、无破框脚本，实测可嵌；这是本页唯一可行方案——自绘需重做其地图/云图/预警数据链路，属另一个项目。
- FR-14.2 **跨域 iframe 内的滚轮由该 iframe 自己的文档消费，父页收不到事件**，因此本页的翻页入口是圆点与键盘，页头须写明该提示（FR-11.3 的既定边界，不是缺陷）。
- FR-14.3 iframe 首次进入本页才挂载 `src`（FR-11.7），挂载后保持不卸载；页头提供"新窗口打开"出口。
- FR-14.4 右侧留一条圆点通道：圆点不得压在云图 / 天气卡右缘或台风网自带的右侧工具条上。

### FR-8 主题（明暗）

- FR-8.1 主题三选一：跟随系统（`prefers-color-scheme`）/ 浅色 / 深色，默认跟随系统。
- FR-8.2 用户在设置页切换，选择存 localStorage，优先级高于系统设置；系统主题变化时"跟随系统"模式实时响应。
- FR-8.3 暗色下毛玻璃卡片、文字对比度保持可读（WCAG AA 级别主观可读即可）。
- FR-8.4 主题必须在首屏绘制前生效：`<head>` 内联同步脚本读单键设置 `nav.settings` 的 `theme`（缺省按系统 `prefers-color-scheme` 解析）写上 `html[data-theme]`，不得等 YAML 请求解析完成——否则深色用户每次进页闪白。内联脚本与 `js/prefs.js` 的键名/结构是同一契约，改一处必须改两处。

### FR-9 （v1.2 废止）插件挂载点

v1.1 曾为"零插件"预留 `#plugin-slot` 容器与注册约定注释。实现中该挂载点从未被任何代码或插件使用，规范与实现已互相矛盾（smoke test 反向断言其不存在），属死代码，v1.2 起从规范与实现双双移除。真实插件需求出现时，另立 FR 重新讨论机制。

### FR-10 设置页（统一收口所有设置）

- FR-10.1 左上角齿轮按钮（`#settings-toggle`）为设置唯一入口，点击弹出浮窗（模态）。
- FR-10.2 浮窗包含：背景选择（缩略图网格）、背景模糊开关、主题（跟随系统/浅色/深色）。后续**站点级**设置项一律加在此处，不再散落在页面上。**内容级选择不算设置项**：第 2 页的云图维度标签、第 3 页的天气城市标签都留在各自页头——它们改的是"这一页看什么"，不是站点的外观或行为，故也都不落盘。
- FR-10.3 **草稿模式**：打开时拷贝当前生效设置进草稿，浮窗内改动只改草稿，不立即影响页面。
- FR-10.4 关闭浮窗时应用配置并持久化。关闭途径：× 按钮 / "应用并关闭" / 点击遮罩 / Esc。
- FR-10.5 设置优先级：localStorage 覆盖 > YAML 默认值。若用户选择与默认一致，则不写入 localStorage（避免 YAML 改动被旧偏好盖住）。v1.2 起全部设置合并为**单键 `nav.settings`**（JSON 对象，含 `background`/`bgBlur`/`theme`/`engine`），只存显式覆盖的字段，无覆盖时整个键删除；旧多键方案（`nav.background` 等四键 + ''/'1'/'0' 三态编码）废弃。
- FR-10.6 浮窗须为**真模态**：声明了 `aria-modal="true"` 就必须真的把焦点关在里面。打开时焦点移入浮窗；`Tab` / `Shift+Tab` 在浮窗内首尾循环、不得逸出到被遮住的页面元素；关闭时焦点交还齿轮按钮。声明了模态语义却不实现焦点约束，属实现缺陷而非"够用即可"。
- FR-10.7 四种关闭途径（× / 应用并关闭 / 点遮罩 / Esc）语义一致：均应用草稿并持久化。本期不提供"放弃改动"路径；若日后新增取消按钮，须显式定义其丢弃草稿的语义，不得沿用现有四条路径。

## 4. 非功能需求

| 编号 | 类别 | 要求 |
|------|------|------|
| NFR-1 | 性能 | 首屏仅请求 HTML/CSS/JS/YAML + pinned 图标；无骨架阻塞，总请求数与 pinned 数量线性相关。脚本统一 `defer`，让浏览器先完成解析与首屏绘制。切换标签不得重建标签栏或重复触发内容区渲染（见 FR-3.4）。v1.4 追加、v1.5 扩充、v1.6 收紧：云图接口、天气接口与台风 iframe 均为首屏之后按需触发（FR-11.7），第 1 页的首屏请求集不因第 2~4 页而增加；天气页无论预设几座城市，一轮刷新固定 2 个请求（FR-13.3），切城零请求（FR-13.4）。 |
| NFR-2 | 可靠性 | 任一外部资源（favicon 服务、行情接口、台风站）失败不影响页面主体渲染；云图失败保留上一帧并显示错误行，台风页失败至多是空白 iframe 加一个"新窗口打开"出口。 |
| NFR-3 | 可维护性 | 新增/删除网站只改 YAML；新增背景只传图 + 改 YAML 清单；新增/删除天气城市只改 `weather.cities`（FR-13.2）。第 2~4 页为内置固定页，其展示逻辑不在 YAML 里（YAML 只提供天气城市这一项数据）。v1.6 追加：YAML 新增顶层段必须同步 `tools/yaml-editor.html`，否则编辑器保存会丢数据（FR-13.10）。 |
| NFR-4 | 安全 | 仓库不含任何密钥/token；不发起携带凭据的跨域请求（行情接口用默认凭据策略，`Access-Control-Allow-Origin: *` 下也不带 cookie）；向第三方图标源请求时不发送 Referer（`referrerpolicy="no-referrer"`），不泄露本站地址。站点与引擎链接只放行 `http/https`。行情接口回写 DOM 的内容一律走 `textContent`，接口字段不得拼成 HTML。 |
| NFR-5 | 体积 | js-yaml 本地文件 + 全部自有资源合计 < 300KB（不含背景图）。v1.1 实测约 120KB；v1.4 新增 treemap/market/deck 三个自有脚本与两页样式，v1.5 再加 weather.js 与天气页样式，全程零第三方库（云图与天气均自绘，即为此条），2026-10-06 实测 132.4KB（HTML 7.6KB + CSS 22.3KB + JS 102.5KB，其中 js-yaml 38.5KB）。仓库内不得保留未被 `index.html` 引用的文件——未被引用的资源既不生效，又撑大部署体积。 |
| NFR-6 | 兼容 | `backdrop-filter`、Grid、`fetch` 缺失时优雅降级，不报错白屏。`transition` 等简写中使用较新语法（如 `display .15s allow-discrete`）时，必须先声明一条不含新语法的基础过渡、再用增强声明覆盖；否则旧浏览器会把整条简写判为非法值，连带丢失 opacity/transform 等全部过渡。`ResizeObserver`、`matchMedia().addEventListener` 按目标浏览器现状直接可用，不再写旧式回落。 |
| NFR-7 | 可访问性 | 自定义控件（标签、齿轮、搜索按钮、背景缩略图、主题分段项、应用按钮、站点卡片、**翻页圆点**）必须提供可见的 `:focus-visible` 焦点环，否则键盘用户会「丢失焦点」。不得用 `aria-live` 包裹每次切换都会整体重建的内容区（会导致整屏朗读）；切换状态由标签/圆点的 `aria-current` 表达。深色模式须通过 `color-scheme` 让原生控件（下拉框、滚动条）一并切换。键盘翻页在焦点位于文本框/下拉时让位给控件自身（`INPUT`/`TEXTAREA`/`SELECT` 与 `contenteditable`）。 |
| NFR-8 | 资源开销 | 不得为大面积重复元素（如数十张卡片、上千个云图格子）添加 `will-change` 提层——那会把优化目标从省内存反转为吃显存。模糊与提层的使用范围以 FR-5.7 为准；deck 位移用单个容器的 `transform`，不引入提层提示。云图格子不吃 `backdrop-filter`（自身不透明，套一层纯耗 GPU）。 |

## 5. 文件结构约定

```
/
├── index.html              # 唯一页面；四页 deck 结构与首屏主题内联脚本
├── README.md               # 使用说明（非需求）
├── css/style.css           # 全部样式；改观感只动这里（桌面翻页布局在文末媒体查询内）
├── js/
│   ├── vendor/js-yaml.min.js   # YAML 解析，本地引入不走 CDN
│   ├── icons.js            # 图标降级链 + 字母坞（纯函数，无 DOM）
│   ├── data.js             # 数据层：YAML → 归一化模型（无 DOM）
│   ├── prefs.js            # localStorage 读写（无 DOM）
│   ├── treemap.js          # 布局层：squarified treemap 纯几何算法（无 DOM、无请求）
│   ├── market.js           # 行情数据层：杰瑞接口 → 市值树 + 色阶/格式化（无 DOM）
│   ├── weather.js          # 天气数据层：Open-Meteo 两接口 → 多城预报模型（无 DOM）
│   ├── deck.js             # 翻页层：全站唯一 wheel/键盘入口，圆点与 transform 位移
│   ├── ui.js               # UI 层：模型 → DOM，交互经 handlers 上报
│   └── app.js              # 组合根：接线 + 持久化 + 按需加载
├── data/sites.yml          # 唯一数据源（导航数据 + 天气预设城市）
├── assets/
│   ├── bg/                 # 背景图
│   └── icon/               # favicon / apple-touch-icon，须全部被 index.html 引用
└── docs/SRS.md
```

分层硬约束（与实现一一对应）：`data.js` / `icons.js` / `prefs.js` / `treemap.js` 不得触碰 DOM、不得发请求；`market.js` / `weather.js` 只发请求与算数值，不得触碰 DOM；`ui.js` 不得 `fetch`、不得读 localStorage、不得解析 YAML、**不得自行监听滚轮**（滚轮入口唯一在 `deck.js`，见 FR-7.3/FR-11.3）；`deck.js` 只认"页"这一层，不渲染任何业务内容，通过 hooks 向 `ui.js` 要判定与动作；`app.js` 不承载业务逻辑，只做接线、持久化与按需加载（FR-11.7）。层间契约 = **归一化模型结构 + CSS 类名**（`.site-card` / `.site-card--pinned` / `.site-icon` / `.site-tile` / `.site-name` / `.tab[aria-current]` / `.dot[aria-current]` / `.bg-thumb[aria-current]` / `.seg-item` / `.tm-ind` / `.tm-grp` / `.tm-leaf` / `.wx-now` / `.wx-air` / `.wx-day` / `.city-item`），重写 UI 只动 `ui.js` + `style.css`。

## 6. 明确不做（Out of Scope）

1. **通用插件机制**：v1.2 起连空挂载点也不保留（见废止的 FR-9）。v1.4~v1.5 落地的云图、天气、台风三页是**内置固定页**，各自有专属数据层与渲染代码，不是插件系统的第一个实例——不做插件注册表、不做第四页之后的通用装载协议。
2. 页面内编辑导航数据、GitHub API 直写、localStorage 数据覆盖层。
3. 后端、代理、构建步骤、前端框架。**为第三方数据自建代理**同样不做：行情接口须本身 CORS 开放才纳入（见 §2.4）。
4. 多用户、多设备同步（localStorage 类设置换设备失效，属可接受行为）。
5. UI 文案多语言。
6. **PWA 化**：webmanifest、Service Worker、离线缓存、`android-chrome-*` 安装图标。本站无安装与离线诉求，为几张图标补一套 manifest 属过度设计；对应图标不纳入仓库（见 §8）。
7. **卡片网格的跨标签缓存 / DOM 复用**：站点规模在数十级，图标重复请求已由浏览器 HTTP 缓存覆盖；为切换标签缓存各标签网格节点只会让常驻 DOM 与内存单调上升，与本项目的省内存目标相悖。（云图格子的按键复用不在此列：那是上千节点每 12s 一帧的必需品，见 FR-12.5。）
8. **云图的个股下钻 / 点击跳转 / 分时图**：源站自身也没启用点击跳转（其 `chart.on('click')` 是注释状态），本项目对齐其"看盘"用途即可。
9. **移动端翻页**：触屏上原生滑动就是翻页，再叠一层手势判定属重复；且 100vh 在移动端浏览器地址栏伸缩时不可靠（见 FR-11.6）。

### 8.5 三页翻页与外部数据源评审结论（v1.4）

### 8.6 天气页评审结论（v1.5）

| 决策点 | 结论 | 否决项及原因 |
|--------|------|--------------|
| 天气数据源 | Open-Meteo 三接口（forecast / air-quality / geocoding），匿名 + CORS 全开 | 中国天气网：页面虽可 iframe（实测无 `X-Frame-Options`）但带站头与广告；其 JSON 接口 `d1.weather.com.cn` 实测无 Referer 403、带 Referer 200，浏览器无法伪造 Referer，数据路线不通 |
| 天气页渲染 | 自绘卡片（当前 + 7 天 + AQI） | iframe：与"插要素"的诉求相反，且又会吃掉滚轮翻页（同 FR-14.2 的边界） |
| 城市来源 | 页内中文搜索 + localStorage 记忆，默认城市为模块常量 | 浏览器定位：多一个授权弹窗，且 Open-Meteo 无反向地理编码，拿到坐标仍不知城市名；写进 YAML：换城市要提交一次，且与"YAML 只管第 1 页"的既定边界冲突 |
| AQI 口径 | 用接口字段 `us_aqi` 并在标签写明"美标" | 混用国内 AQI 数值口径：接口不直接给国标数值，硬换算会给出错误分级 |
| 空气质量失败处置 | 单独 `.catch` 降级为无 AQI 块 | 与主数据同一个 `Promise.all`：一个附加信息源抖动就整页报错 |
| 星期标签算法 | 以接口 `daily[0]` 为"当地今天"顺推 | `new Date('YYYY-MM-DD')` + `getDay()`：该形式按 UTC 解析，东八区会整体偏一天 |
| 刷新周期 | 10 分钟 | 沿用云图的 12s：上游逐小时更新，12s 只是白耗请求 |
| 状态行位置 | 与卡片同级、在可重建网格之外 | 放进 `#weather-grid` 后整体 `textContent = ''` 重建：状态节点被连带删除，此后加载/失败提示全部写进游离节点（v1.5 实测中真实踩到并修正，固化为 FR-13.7） |
| 页序与编号 | 天气插为第 3 页 = FR-13，台风顺延为第 4 页 = FR-14 | 让 FR 编号跟随插入顺序而页序倒挂（FR-13 是台风、FR-14 是天气）：读需求时要来回跳，改号成本更低 |

### 8.8 代码走查结论（v1.7 · 云图流畅度与精简）

| 决策点 | 结论 | 否决项及原因 |
|--------|------|--------------|
| 云图几何重算 | `packTree` 结果按「树引用 + 容器尺寸」缓存，轮询 / 切维度只重绘颜色与文字（FR-12.5） | 原实现每轮都跑完整 `packTree`：市值树权重恒定、尺寸未变时几何完全一样，却对全树 5000+ 节点重排，与 FR-12.5「每轮只改样式与文本」直接冲突；点 6 个维度每次都全量重排、切换有卡顿 |
| 悬停 tooltip 绘制 | `mousemove` 合帧到 `requestAnimationFrame`，`#market` 与 tooltip 矩形缓存复用（FR-12.6） | 原实现逐 `mousemove` 读 2 次 `getBoundingClientRect` 再写 `transform`：读→写→(下事件)读，在上千格子的子树上反复强制回流；快速扫过时每个像素移动都触发 2 次全子树 reflow |
| `NavTreemap.squarify` 导出 | 移除（仅 `packTree` 内部调用） | 对外导出却全仓无外部调用，属死 API；`treemap.js` 的层间契约只需 `packTree` |
| market / weather 轮询机件 | **不抽公共 poller**，两套各自保留 | 二者差异真实（市场有 `setDimension` + 树缓存，天气有 `refresh` + 多城合并）；抽公共层反增一层间接，与本轮「减少过度设计」目标相反——两处约 40 行的相似胜过一次过早抽象 |
